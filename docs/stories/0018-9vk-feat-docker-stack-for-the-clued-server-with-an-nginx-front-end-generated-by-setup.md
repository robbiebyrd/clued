# Docker stack for the clued server with an nginx front-end, generated by setup

## Problem Statement

The clued server exists (`mind-palace server run`, `Dockerfile.server`, `docker-compose.server.yml`), but running it is an operator's manual job: mint a token, prepare certificates or a reverse proxy, edit the compose file, then copy the URL, token and CA into the client config by hand. `/clued-setup` offers only a local MongoDB or a server someone else runs.

The compose file also publishes plain HTTP on loopback only and leaves TLS entirely to a proxy the operator has to set up, so a one-machine or small-team deployment has no HTTPS at all out of the box.

**Impact:** Most users never get a server, so sessions, plans and stories stay on one machine; a cloud container cannot be pointed at anything.

## Steps

### 1: `mind-palace server init`

A `server/stack` package (business rules) and the `server init` command generate a stack directory (default `~/.clued-server`): `docker-compose.yml` with `mongo`, `clued-server` (plain HTTP behind the proxy, never published off loopback) and, by default, `nginx` terminating TLS on the public port; `nginx/clued.conf` with the proxy rules of `docs/server.md`; `mind-palace.config.yaml`; a private CA and a leaf certificate under `tls/` whose SANs cover localhost, the host name and every `--host`; and a token minted into `tokens.json`. `--proxy none` leaves nginx out and publishes the server on loopback for another terminator; `--no-tls` keeps user-supplied certificates (mkcert); rerunning keeps `tls/` and `tokens.json` unless `--force`. The image tag follows the plugin version the shim exports as `CLUED_PLUGIN_VERSION`.

### 2: Setup, uninstall and hooks

`/clued-setup` (command and skill) gains the option to run the server in Docker on this machine: `server init`, `docker compose up -d`, wait for `/health`, write `config.json` with the URL, token and CA file, then the existing server checks. `hooks/uninstall` and `/clued-uninstall` stop the stack (`docker compose down`, data volume kept unless asked).

### 3: Tests

`server/stack` tests cover the generated files, the certificate chain and SANs, idempotence, `--force`, `--proxy none` and `--no-tls`; a CLI test runs `server run` with the generated certificate and reaches it through the remote client with the generated CA; the root `docker-compose.server.yml` gains the nginx service and both compose files are validated with `docker compose config` when the CLI is installed; plugin tests cover the uninstall stop.

### 4: Docs

README (install, remote mode), `docs/server.md` (a Docker section built on `server init`, nginx and the other terminators), CLAUDE.md layout and the setup and uninstall commands describe the stack and state that plans and stories keep their markdown files as the primary store and fan out to the server.
